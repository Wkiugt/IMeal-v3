## 1. Purpose and evidence boundary

This record makes the unresolved metrics decisions explicit before implementation. The authoritative required-name list is the `HARDENING_METRIC_NAMES` list in `scripts/staging/runtime-integration.mjs:12-36`; it contains exactly 23 names. The same consumer requires every name in the internal metrics response (`scripts/staging/runtime-integration.mjs:196-249`). It public-probes the API `/metrics` path to ensure it is not reachable, then requires HTTP 200 and all 23 names from the internal worker monitoring origin (`scripts/staging/runtime-integration.mjs:306-329`).

The staging design provides observability categories and initial alert policy, but says the exact exporter is a deployment decision (`docs/superpowers/specs/2026-09-28-staging-readiness-design.md:402-432`). The production-hardening plan provides request-ID, logging, health, lifecycle, and migration-evidence primitives; it does not provide a concrete metrics collector/exporter or producer contract (`docs/superpowers/plans/2026-09-28-production-hardening-plan.md:29-57,69-126`). The staging plan explicitly consumes hardening-owned metrics and must not define or reimplement runtime collectors (`docs/superpowers/plans/2026-09-28-staging-readiness-plan.md:514-581`).

Therefore `STG-METRICS-01` remains **BLOCKED**. Application-only constants, zeros, or synthetic values for infrastructure, storage, backup/restore, or security signals would be misleading and would violate the fail-closed release gate. No metrics endpoint is claimed to exist.

### 1.1 User-approved architecture and source boundaries (2026-09-30)

The following decisions are **APPROVED BY USER** for the implementation plan. They settle architecture and authoritative source boundaries; they do not by themselves settle the concrete row-level labels, values, bucket boundaries, freshness rules, or deployment bindings that remain unresolved below.

- **D1:** Hybrid architecture; application/API/worker instrument only application metrics; authoritative separate sources for PostgreSQL/PgBouncer, object storage, backup/restore, security; no synthetic metrics.
- **D2:** Internal private `/metrics`; no public Caddy/API exposure.
- **D3:** API/worker: request/auth/OTP/serving/idempotency/worker; fixed bounded labels/enums; stable buckets; counter reset on restart; dependency unavailable = stale/unknown/collector failure; exclude `/metrics` from HTTP metrics.
- **D4:** Authoritative PostgreSQL/PgBouncer source/exporter/custom least-privilege queries: real connection/pool, lock waits, disk, DB-scope transaction errors; stale/unknown when unavailable.
- **D5:** Private MinIO/storage-platform source; usable capacity and bounded storage telemetry.
- **D6:** Backup/restore pipeline authoritative; manifest/checksum/restore artifacts.
- **D7:** Independent Caddy/WAF/TLS/scanner/external security source with bounded taxonomy and deduplication.
- **D8:** Explicit allowlists, no secrets/PII, every metric records type/unit/labels/values/cardinality/buckets/interval/stale/reset/retention.
- **D9:** Evidence gates unchanged; decision approval permits implementation only, not `STG-METRICS-01` PASS.

The approval does not authorize application-local approximations for D4–D7, does not claim that a producer or endpoint exists, and does not change the external staging/release gate.

## 2. Observed endpoint and isolation contract

The following is the current consumer contract, not evidence that the producer exists:

This is a contract boundary, not evidence that any producer, transport, or endpoint is deployed.

## 3. Required metric rows

The table below resolves the implementation schema for all 23 required names. It does not claim that any producer, transport, endpoint, credential, target, or evidence artifact exists.

**Common contract for every row:**

- Application producers are `ApiApplicationMetricsAdapter` (API request/auth/serving/idempotency samples) and `WorkerApplicationMetricsAdapter` (OTP/outbox/worker-run samples). Both send bounded samples to the `WorkerMetricsAggregator` over the approved private monitoring transport. The aggregator alone may render the internal worker-origin `/metrics`; the API has no metrics route.
- Authoritative producers are `PostgresAuthoritativeMetricsAdapter`, `ObjectStorageAuthoritativeMetricsAdapter`, `BackupRestoreEvidenceAdapter`, and `SecurityBoundaryEvidenceAdapter`. They MUST read the real source named in their row and MUST NOT substitute application logs, constants, or zeroes.
- Application and worker samples are observed every **30 seconds** and become `stale` after **60 seconds** without a fresh valid observation. Authoritative adapters are observed every **60 seconds** and become `stale` after **120 seconds**. `unknown` means the source responded but omitted or could not establish a value; `collector_failure` means unreachable source, missing runtime configuration, authorization failure, parse/schema failure, or invalid evidence.
- A non-`fresh` required sample is not rendered as a numeric metric. The aggregator records the state in redacted diagnostic/evidence metadata and refuses an HTTP 200 complete snapshot until every required source is fresh. It never turns `unknown`, `stale`, or `collector_failure` into zero.
- Application counters and histograms reset when their process restarts; no persistence, rebasing, or cross-process smoothing is permitted. External counters retain the source value; a detected source reset is recorded in evidence and the adapter starts a new source baseline without emitting a synthetic delta. Gauge values are replaced by the newest valid observation.
- Emitted metric-series retention is **30 days**. Each observation binds `release`, service/source identity, canonical observed-at timestamp, contract revision, freshness state, and a SHA-256 digest of the redacted snapshot/evidence. Raw database, storage, backup, and security artifacts remain outside this repository under the external retention policy recorded at qualification.
- The endpoint contract is the existing private worker-origin `/metrics` consumer (`scripts/staging/runtime-integration.mjs:196-249`); public API/edge `/metrics` remains non-success (`:306-312`, `infra/staging/Caddyfile:22-27`). These rows do not implement that endpoint.

## 4. Redaction, labels, and cardinality rules

These are the resolved safety and cardinality constraints for the contract; they do not claim that the producers or endpoint are deployed:

- Metric output and evidence MUST NOT contain OTP values, bearer/session tokens, provider payloads/API keys, database URLs, raw GPS, unredacted employee/location data, credentials, or other secret-bearing values (`docs/superpowers/plans/2026-09-28-staging-readiness-plan.md:20-25`; `docs/superpowers/specs/2026-09-28-production-hardening-design.md:398-400`).
- HTTP labels are exactly `{route,method,status}` with the finite enums in M-01. Auth/serving labels are exactly the finite `{result}` enums in M-03/M-08; worker labels are exactly the finite `{job,status}` enums in M-11. External labels are only the finite enums explicitly listed in M-14, M-19, and M-23. All other rows have no labels.
- Raw request IDs, user IDs, email addresses, employee codes, location names, QR/session values, provider payloads, target URLs, credentials, or arbitrary exception text are forbidden as labels and values. Cardinality is bounded by the enumerations in the row table; `other` is the only bounded HTTP route fallback.
- Both histograms use the fixed seconds buckets `0.005`, `0.01`, `0.025`, `0.05`, `0.1`, `0.25`, `0.5`, `1`, `2.5`, `5`, `10`, `+Inf`; `le` is required. Bucket changes require a contract revision.
- Application/worker observation is every 30 seconds with a 60-second stale limit; authoritative-source observation is every 60 seconds with a 120-second stale limit. Metric-series retention is 30 days. Counter reset and non-fresh state handling are defined in the common contract and each row.
- `unknown`, `stale`, and `collector_failure` are diagnostic/evidence states, not numeric metric values. A missing or failed required source makes the internal collector incomplete and prevents HTTP 200; it is never represented by a constant or zero.
- Public `/metrics` success is forbidden. The worker-origin endpoint remains private and is not implemented by this document.

## 5. Evidence and approval gates

`STG-METRICS-01` cannot move from **BLOCKED** based on source presence, mocked fixtures, metric-name presence, zero values, or a local Docker build. The minimum proof sequence is:

1. A named runtime/platform owner reviews and records acceptance of this concrete contract, including the API-to-worker transport and external adapter boundaries.
2. The 23-row contract is approved for implementation scope, including real source, type/unit, labels/cardinality, freshness, failure behavior, reset/retention, and evidence binding for every row.
3. Ownership-aligned collectors/exporters are implemented without changing the staging consumer into a producer.
